# QQ 主动联系

范围：接入现有 PostgreSQL、人设和记忆，只向已绑定本地 Owner 的 QQ 主号私聊。不开群聊，不另装主动消息插件。验收包括计时持久化、一次发送后暂停、回复重置、免打扰、设置页面、真实模型预览及并发/中断处理。

## 使用

打开 **Bot 设置 → 主动联系**。默认开启，间隔为 **10～14 小时**，免打扰为 **北京时间 00:00～08:00**。界面可修改开关、最短/最长间隔和免打扰起止时间，也能看到排期与最近 20 次记录。

- 用户在 QQ 或 Web 发来新消息时，使用系统随机数抽取一次等待时长并保存。Bot 自己回复、检索、预览不重新计时。
- 到点时若在免打扰期间，延后到免打扰结束。支持跨午夜；开始时间包含、结束时间不包含。
- 发出一条后一直暂停，直到用户再发来消息。关闭再开启不解除等待回复。
- QQ 离线、绑定失效、Bot 正在忙、功能关闭或免打扰时，不调用模型生成主动消息。每 60 秒检查一次本地状态。
- 电脑需要在线且 Bot 运行。重启后恢复 PG 排期；已过期排期至少等待两分钟，再检查免打扰，不补发多条离线消息。
- 模型可以根据用户说过的“今天忙”“先别找我”等内容选择保持安静。这种情况下不消耗发送机会，再随机等待一次。时间段免打扰由程序硬性保证。
- “生成一次预览（不发送）”会调用模型并展示结果，不写入假用户消息、不发 QQ、不消耗联系机会。

## 人设、记忆与上下文

正常回复与主动消息共用 `CompanionMemory.companion_context`：PG 的 L0 固定人设、已批准且未暂停的 L1、核心事实、相关活跃/归档记忆及一条随机归档记忆，以及连续对话的原文和摘要。主动任务使用最新真实用户消息作为来源，并把它之后的真实助手回复一起纳入历史，避免从上次用户发言重新回答。

L0 > L1 > L2 的优先级不变。无新消息时不伪造用户事件；主动生成没有工具，不能批准人设变更或确认记忆。成功送达后仅把真实发出的内容以 assistant 角色存入 PG，供后续 QQ/Web 交流和每日整理使用。每日整理仍以用户原话为事实证据；普通记忆的 10 级、48 小时降一级、低于 7 归档等规则均不变。

使用现有 DeepSeek Flash 配置、正式的 API 用量记录器和上下文预算。主动短消息的输出预留为 1000 Token，解析后的正文最多 500 Token；上下文按现有策略按需展开。记录分类为 `proactive` 和 `proactive_preview`，可在“用量与连续性”查看实际输入/输出、缓存和费用。每分钟的状态检查不消耗模型 Token。

## 持久化和发送一致性

- `proactive_settings`：设置。
- `proactive_state`：最新用户来源、随机间隔、到期时间、等待回复、当前任务和失败次数。
- `proactive_deliveries`：生成/取消/跳过/发送/未知等审计，目标和 OneBot 回执。

计时与用户消息在同一数据库事务提交。PG 事务锁和任务标识避免并发领取；网络调用期间不持有 PG 锁。生成之后再次检查绑定、连接、人设版本、免打扰、开关和用户最新消息。生成过程中用户回来或修改设置，旧任务取消。

发送前先在 PG 将这一轮记为等待回复，再调用原生 OneBot `send_private_msg`，只有返回消息 ID 才记为已发送并写入对话。发送超时、回执缺失或发送中断记为“结果未确认”，继续等待用户回复，**不自动重发**。这在网络无法提供原子提交时优先避免重复打扰；可能有一条实际未送达但本轮仍暂停，可在界面核对。

生成限时 180 秒，生成失败间隔五分钟重试，最多三次，之后等用户回复重新开始。QQ 发送限时 30 秒；发送中重启按未知结果处理。用户在网络发送期间已经回复，也不会被较晚返回的回执覆盖新计时。网络请求提交后的极短竞争窗口无法撤回已进入 QQ 的消息。

## 本地接口

以下路径都在 `/api/v1/plugins/extensions/astrbot_plugin_companion_memory/` 下，沿用现有仅本机访问保护：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `proactive` | 设置、排期、QQ 是否就绪、调度器错误、最近记录 |
| POST | `proactive` | 保存完整设置；间隔范围 0.25～168 小时，最长不得小于最短 |
| POST | `proactive/preview` | 调用真实上下文与模型预览；永不发送 |

回滚：在页面关闭主动联系即停止新任务；现有聊天和记忆仍保留。需要回退代码可使用引入前提交 `30c1a9c`；新增表不影响旧版，不需要删除数据。没有创建数据库备份，也没有清空用户聊天或设定。

## 验证边界

使用隔离 PG schema 测试随机排期、跨平台回复、等待回复、免打扰、并发、状态变化、失败上限及重启恢复；对外 QQ 发送在这些测试中使用带回执的替身。另通过实际服务/API、浏览器和 DeepSeek 预览验证接入。10～14 小时真实等待和实际到点 QQ 推送，需要随后在线运行观察，不能由加速测试替代。
