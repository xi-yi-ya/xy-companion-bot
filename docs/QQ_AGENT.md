# QQ 账号能力与统一权限

2026-11-01，插件 v0.10.0。复用现有 NapCat v4.18.42 / OneBot 11 与 AstrBot 工具注册，不另装协议或账号管理插件，不修改 vendor。

入口：**Bot 设置 → QQ 连接 → 账号权限与操作**。

## 权限清单

| 能力 | 默认行为 | 授权方式 |
| --- | --- | --- |
| 查看好友、已加入的群、群成员 | 主人私聊中按需查询真实接口 | 群成员无法调用账号工具 |
| 好友申请 | 进入待处理列表，不自动通过陌生账号 | 本地页面通过/拒绝；可选账号白名单自动通过 |
| 群邀请 | 进入待处理列表；不审批其他成员申请入群 | 本地处理；可选群号白名单自动加入 |
| 新加入群 | 只读，不回复、不发附件 | 每群分别开读取、回复、附件权限；未知群默认拒绝读取 |
| 已有群 | 首次迁移当前已加入群，保留原来的文字参与范围 | 原“参与群号”与新权限同时生效；附件默认关闭 |
| 其他好友私聊 | 默认只响应绑定主号 | 可增设允许聊天的账号；各自独立记忆，不能管理账号 |
| 引用 | 沿用按需引用 | 只选真实会话消息；可在聊天方式关闭 |
| 发图/文件 | 可发给主人，使用明确加入素材库的文件或新建文本 | 分别设置发图、发文件开关；其他私聊需白名单，群附件需单独授权 |
| 撤回 | 可尝试撤回本版本记录到回执的 Bot 消息 | 不撤回别人消息，失败如实返回，不保证 QQ 允许过期撤回 |
| 急停 | 页面一键开启 | 阻止新的 QQ 收发、申请处理、主动联系、空间读写；本地手动解除 |
| 空间说说 | 独立开关、最短间隔和每日上限 | 参见 [空间阅读与自主发布](QZONE.md) |
| 点赞、评论、踢人、禁言、解散群、任意 API / Shell | 不开放给模型 | 不受好友/进群权限隐式授权 |

首次迁移账号后，不再自动授予未知群权限。通过 Bot 处理的邀请在加入前先创建只读规则；收到小号自身入群通知也创建只读规则。若离线时加入而没有收到通知，在页面添加群规则后才读取。

## 数据和执行链路

消息来源记录在 `messages.platform / platform_id / chat_type / group_id / sender_id`；`person_id` 继续表示记忆归属，`conversation_id` 表示会话。群聊记录保留实际发言人，不能用共享房间的记忆账号冒充某个群成员。老记录按可信格式回填；无法确定的账号保持 NULL。

申请在消息唤醒/主号过滤前接收，写 `qq_requests`，不会伪装用户聊天送进模型。申请的 OneBot `flag` 只在执行层保存，模型与设置页不接收它。重复事件不会重复处理，已决定的申请不能被后续相反决定改写。

模型选择的是受限工具。执行层再次检查当前 Bot 账号、目标与即时权限，先在 PG `qq_operations` 写入预占，再向 OneBot 发出一次操作。普通 QQ 文字回复与主动联系也经过发送守卫记录真实消息编号，供查询和撤回。没有回执的发送标记 `unknown`，不自动重试；重载遗留的发送同样保留为未知。账号目录只记录读取类型与数量，不把整份好友名录复制进日志。

DeepSeek 的运行配置必须包含 `tool_use`。本次同时修复原启动配置仅声明 text/image、导致 AstrBot 清空工具清单的问题；启动时迁移已有配置，插件运行时也校正模型能力。`api_usage.usage.offered_tools` 记录实际发给 API 的工具名，与输入输出 Token 一起观测；不把提示词里“说有工具”当成已传入工具。

急停在收消息、生成结果和真正调用发送接口前均检查；已经进入网络的请求无法保证取消。重载时撤除旧发送包装，等待本插件在途操作退出，再关 PG，避免再次引用已关闭连接池。

普通文字转发与工具发送统一规范 `self_id`，避免已有参数被重复注入。该问题曾影响本轮联调中的 QQ 文字及主动联系，修复后主号已确认测试消息和普通回复恢复。主动联系页增加独立连通测试，不改自动联系排期；当前实例保留主人设置的间隔。

DeepSeek 官方地址固定直连。错误日志显示此前部分连接经过本机 SOCKS 代理并在 TLS 握手被关闭；采用 HTTPX 0.28.1 按精确主机名分配直连 transport，其他域名继续保留代理。不会关闭在途请求或原连接池，transport 随 SDK 客户端退出回收。启动时也追加进程级 NO_PROXY；实际请求记录 `usage.network_route`。这修复本机已观察到的代理路径，不承诺远端服务永不出现网络故障。

素材库位于运行目录的 QQ `outbox`，只向模型展示文件 ID、名字、类型与大小。模型不能提供任意本机路径；文件在发送前检查实际路径仍位于素材目录。上传支持最大 20MB 的常规图片和文档；模型可新建 1MB 内的 UTF-8 txt/md/csv/json。附件额外限制每分钟 10 条、滚动 24 小时 100 条，未知结果也计数；普通文字聊天不受此附件额度影响。

L0/L1 修改仍走原人工审批；QQ 权限不授予改人设、读取他人私聊、修改记忆或向外传播主号私聊的权限。

## 工具

`companion_qq_directory`、`companion_qq_requests`、`companion_qq_handle_request`、`companion_qq_assets`、`companion_qq_create_file`、`companion_qq_send_media`、`companion_qq_recall` 仅向主人私聊提供。状态和权限每轮明确注入，群聊只接收本群上下文，不注入主人私聊、好友名录或账号管理能力。

## 复用依据与验证

- [NapCat 官方 API](https://napneko.github.io/onebot/api)：目录、好友申请、群邀请、发送、撤回。
- [NapCat 消息段](https://napneko.github.io/onebot/segment)：原生 reply / image / file；保留实际消息编号，便于撤回。
- [OneBot 请求事件](https://github.com/botuniverse/onebot-11/blob/master/event/request.md)：区分好友请求、邀请 Bot 入群与其他成员入群申请。
- AstrBot 固定 v4.29.4 的本机源码确认请求会转换为 `raw_message`，插件在原有唤醒守卫中接收，无需改框架。

隔离 PG 测试覆盖权限、重复事件、相反决定、账号隔离、目录/附件边界、未知回执、重启恢复、旧守卫迁移、发送包装交接、急停和真实发言人回填。`qq_agent_browser_test.cjs` 验证设置保存/刷新、急停和发布设置；`qq_capabilities_live_test.py` 验证实际模型工具链并只清理本轮技术聊天。未制造陌生人申请或邀请 Bot 加入外部群，因此真实好友/群审批需下一条实际申请观察，不能把模拟回执当作已通过真实申请。

实测好友与群目录读取成功、文件成功送至绑定主号。图片发送、撤回均成功，并收到 QQ 本人的撤回通知。首次真实文件撤回被 QQ 接口拒绝；另一次文件发送遇到原生 sendMsg 回调超时，按未知结果保留，不补发。不能把实现了撤回接口表述为所有文件都能追回。撤回操作按协议不产生新消息编号，日志关联的是原消息编号，空的新消息编号本身不表示撤回失败。

回滚时先在页面急停，再回退代码；保留新增 PG 表与来源记录。不清除人设、历史或记忆，无数据库备份。
