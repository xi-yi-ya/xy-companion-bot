# QQ 空间阅读、分享与自主说说

2026-11-01，插件 v0.10.0。

## 使用

入口：**Bot 设置 → QQ 空间**。默认开启浏览和分享候选，浏览间隔在 **15～30 分钟**之间随机选择，可修改开关、最短与最长间隔；保存后重新安排下一次浏览。页面显示排期、最近浏览、错误和候选的原文、来源及阅读笔记。

“检查空间登录”只检查小号当前可读的空间接口；“现在浏览一次”读取并整理新内容，不绕过发送规则。QQ 必须在线且已绑定主人。登录态优先从现有 OneBot 获取，每轮重新取用，只在内存中使用，不写进聊天、PG、源码、日志或 GitHub；不需要提供另一把 API Key。

自主发布按主人的明确授权接入下方独立开关与频率限制；**点赞、评论、删除说说均没有开放给模型**。

聊天中的 `companion_qzone_status` 查询真实状态，`companion_qzone_read` 可以实际读取绑定主号或指定 QQ 可见的空间。手动读取不受自动浏览开关控制，仍要求小号在线及主人私聊。好友流为空时，后台尝试读取绑定主号空间；解析保留实际作者，不把好友动态误归属小号。读取错误会返回真实状态，不把权限失败当作“没有动态”。

手动指定条数同时约束当前拉回内容和本轮笔记，不额外处理历史页的旧待办。笔记任务把私聊历史当作参考资料，不继续执行历史用户指令；笔记生成失败时仍返回已经读到的真实动态，并单独标记笔记未完成。不会再把“阅读笔记 JSON 失败”说成“空间一条也没读到”。

此前“Bot 说没有接口”有两层缺口：只接后台浏览，聊天没有实际读取工具；模型配置又漏了 `tool_use`，AstrBot 会在请求前清空工具清单，Flash 因而可能把 DSML 当正文输出。现在修正启动配置和运行时能力，明确选入当前已注册的 companion 工具；每轮注入真实能力与状态，实际 API 用量记录附带本次提供的工具名，便于发现再次漏接。文本格式的只读工具调用仍有受限恢复，不能借此执行发布或其他账号操作。

## 阅读、人设与记忆

- 每轮最多保留当前页 20 条动态；按账号、作者、应用及动态 ID 去重。空列表和已经整理的内容不调用阅读模型。
- 每轮整理最多 12 条尚未读过、最近 7 天内的动态；不明发布时间的动态保留来源，不能虚构发布时间。初次打开不会强制翻完所有历史。
- 使用现有 **DeepSeek Flash、L0、已批准 L1、私人近期对话和相关记忆**判断兴趣，允许一条也不挑。最多形成 3 条分享候选。
- 最多解析 3 张配图，沿用原有附件下载与视觉解析；明确记录未读取/未能读取的图片，不假称看过其余图片或视频。原文和阅读笔记分开，笔记中的图片描述来自实际图片解析结果。
- `qzone_posts` 保留有作者、来源、读取时间的观察，`qzone_candidates` 保留兴趣与笔记。它们不会冒充用户发言，不会自动转成用户的核心事实或情景记忆。
- 主人私聊问到空间、刷到什么或刚在忙什么时，按预算注入最近的真实阅读资料；不会把这些私人观察注入群聊。
- 每日整理、10 级初始记忆、每两天降一级、8 天归档、用户确认才强化等规则保持原样。真实分享成功后，发送文本也进入原有 PG 聊天历史，后续可继续讨论。

## 分享节奏

候选接入原有主动联系服务，沿用 **10～14 小时等待、免打扰、用户新消息重新计时、发出一条后等用户回复**。15～30 分钟是浏览间隔，不是私聊打扰间隔。关闭“主动联系”或空间分享开关都会阻止自动发送。

生成分享时重新使用当前人设，选择合适内容才发送，并附真实原动态链接。候选最多在 72 小时内参与自动分享选择。发送前在同一 PG 事务检查主人、Bot 账号、设置版本、候选状态和免打扰，预先占用一次发送机会；回执不确定标记 `unknown`，不重复补发。分享仅发给已绑定主号。

## 实现与来源

独立只读 HTTP 适配器 `qzone_http.py` 只请求 QQ 空间阅读地址，不加载第三方 daemon。QQ H5 首页可能正常跳转桌面首页，此时继续尝试只读好友动态接口；指定作者走用户说说列表。不向登录页或第三方地址转发 Cookie。单页响应有大小上限。

纯数据解析复用 [QzoneUltra](https://github.com/diaomin66/astrbot_plugin_qzone_ultra) 的 `parser.py`、`social.py`、`models.py`、`utils.py`，固定提交 `4221713b508bf2a88e43e75d1719458d2f69764f`。文件位于 `plugin/qzone_read/`，随附上游 MIT LICENSE，未安装其完整插件，也没有增加依赖包。

新增 PG 表：`qzone_settings`、`qzone_state`、`qzone_runs`、`qzone_posts`、`qzone_candidates`。后台任务以持久化排期和 5 分钟租约避免重复运行，重载会取消并等待正在运行的自动/手动浏览，再关闭连接池；失败后按随机间隔安排下一轮，不快速重试。

## 自主写说说与发布

入口：**Bot 设置 → QQ 空间 → 她自己的说说**。新安装默认关闭；本机按主人明确授权开启。建议设置 **最短 12 小时、北京时间每天最多 2 条**，可分别调整。15～30 分钟的浏览排期不等于发说说频率。

首次考虑随机等待 15～30 分钟，选择不发后随机 60～120 分钟再考虑；到达时间只说明可以写，不要求一定发。最短间隔跨午夜继续生效，每日额度按北京时间日历日计算。预览不发布、不消耗发布额度；手动“现在考虑发布”和聊天 `companion_qzone_consider` 均不能绕过开关、额度或最短间隔。

公开写作只使用当前 L0、已批准的表达/互动风格、当前时间和 Bot 自己的既往说说。私人聊天、用户核心事实、共同秘密、好友原文不提供给公开写作任务。只发纯文字，最多 1200 Token；不虚构线下生活。独立模型检查加程序检查阻止联系方式、凭据、内部工具格式及近似重复。准备发送时重新检查设置版本、账号、人设版本和额度，先在 PG 预占再 POST 一次。

独立 `qzone_publish_http.py` 复用固定上游版本的纯文字发表参数，仅请求小号自己的说说发布地址；不开放通用 HTTP 写入、相册、点赞、评论或好友操作，不修改整个空间访问权限，不同步微博。只有拿到真实说说 ID 才记录 `sent`。响应丢失或没有 ID 时记录 `unknown`，占用间隔和每日额度，不补发。明确拒绝为 `failed`，连续三次技术失败会暂停自动尝试，可检查登录后保存设置重新启动。

设置页显示排期、当日额度、成功/未知/失败记录与真实链接。PG 新增 `qzone_publish_settings`、`qzone_publish_state`、`qzone_publications`；公开说说不会伪装成主号的聊天或记忆确认。费用分类是 `qzone_publish_draft`（输出 2000 Token）与 `qzone_publish_check`（800 Token），按实际 API 用量记账。

真实 Token 用量沿用 `api_usage`，分类为 `qzone_review`、`qzone_vision` 和原有 `proactive`；阅读输出上限 6000 Token，单张视觉解析 2000 Token，实际分享继续遵守原有短消息预算。没有新内容不为了凑预算调用模型。

## 验证与回退

- 隔离 PG 测试覆盖随机排期、去重、无新内容不调模型、租约恢复、关闭期间不生成候选、只读请求、登录跳转、错误账号拒绝、来源验证、既有主动联系限制、关闭分享与不确定回执不重发。
- v0.8.0 首次验证返回 0 条可读动态；v0.10.0 指定作者接口接入后，已从绑定主号空间读到真实动态并保存阅读笔记。不能把好友流空列表解释成“没有工具”或“好友从没发动态”。
- 最终聊天工具链实测读取主号 3 条动态，运行状态 complete，笔记无错误。自主发布已开启为 12 小时 / 2 条每天；预览成功，首次实际考虑选择不发（skipped），没有为验收强行发技术说说，因此真实发表 POST 尚未触发。协议与回执处理由隔离 HTTP/PG 测试覆盖，后续应以首条真实发布回执继续核验。
- `qzone_model_live_test.py` 在临时 schema 使用当前真实 L0 与真实 Flash：2 条合成动态被整理，模型选中 1 条；再次浏览没有重复模型调用；实际调用 2 次，API 返回输入 1581 / 输出 230 Token。分享发送状态机使用本地回执模拟，不向真实账号发技术样本；临时 schema 已清理。
- 该次模型分享预览选择了保持安静；这是允许的结果，不把它报告成真实主动分享。真实好友动态的图片与实际主动私聊仍需后续正常内容触发观察，不能把合成验收写成真实好友内容验收。
- 浏览器验证 15～30 默认值、开关保存并刷新保持、自动刷新不覆盖输入草稿，以及只读说明；最后恢复自动浏览与分享候选开启。

关闭空间浏览即可停止新任务，关闭分享或主动联系即可阻止发送。回退代码时保留新增表和已读来源，不需要删除聊天、人设或现有记忆；本次未创建数据库备份。
