# 插件重载后 PoolClosed 修复

2026-11-01。用户实际错误：`All chat models failed: PoolClosed: the pool 'pool-1' is already closed`。

根因是用量统计的 SDK `create` 钩子闭包持有旧 `UsageRecorder` 与旧 PG 连接池；插件重载关闭旧池后，模型客户端仍在运行，而 `_companion_metered` 标记让新实例跳过重新安装。因此状态页的当前连接池正常，真正调用模型却先进入旧计量钩子并失败。

修复包含：

- 计量钩子记录当前所有者和原始 SDK 方法；新实例重新绑定原始调用，避免套多层钩子。
- 对旧版本遗留钩子，只从本插件自己的闭包恢复其原始 SDK 方法，兼容当前已经出现故障的运行实例。
- 卸载只移除自己仍持有的钩子，旧实例迟到的卸载不能拆掉新实例。
- 重载期间已经完成的模型响应由当前有效计量器记录；关闭中的计量池不能把有效模型结果变成聊天错误。
- 插件先停止并等待接收窗口、主动联系、空间自动/手动浏览和每日任务，再卸载计量钩子、关闭池。退出时标记未就绪。

回归测试包含真实 PG 的旧池已关闭、连续安装不重复计费、旧钩子迁移、在途响应跨重载，以及手动空间浏览先取消再关闭池。

`usage_reload_live_test.py` 在真实后端执行两次插件重载，并在每次重载后调用真实 DeepSeek 聊天：两次成功，每次真实用量各记录一次。该验证在加入 QQ 空间后再次通过。仅清理自己的技术 Web 会话，并在锁内恢复主动联系状态，不删除真实用户消息或修改人设。
