# QQ 按需引用、群聊扫描与连发合并

2026-11-01，插件 v0.7.0。复用 AstrBot / OneBot 的消息链和原生模型链路，在项目插件内增加 PG 适配；未安装额外插件，未修改 vendor。群聊参与判断使用现有 DeepSeek Flash，实际用量归入 `group_scan`。

## 行为

- **引用**：保留读懂引用原文、图片和文件的能力。发送默认“按需引用”，普通接话没有引用；模型确有需要时通过 `companion_reply_to` 选择本轮真实输入 ID，不能编造任意引用目标。设置另有“不引用”和“总是引用”。
- **群聊**：默认无需 @，在线收到的新消息按固定 **10 秒**节拍合并查看；不同成员在同一批内标记姓名与 QQ，群与群分开。没有新消息不调用模型，不重读或重复回复已经处理的批次。
- **是否接话**：明确 @ 或直接叫 Bot 名字时进入回答；其余批次用最多约 7000 Token 的本群资料进行参与判断，输出预留 512 Token。不相关、别人互聊或判断失败时保持安静，不强制每 10 秒发一条。正式回答继续使用原有人设、记忆和完整上下文预算。
- **设置**：Bot 设置 → QQ 连接：扫描开关、间隔（1～600 秒）、参与群号、引用模式、私聊连发等待。关闭扫描恢复仅 @ 触发；填写群号后只参与选定群。v0.10.0 起还需符合下方逐群权限；其他私聊账号需单独授权，各自独立记忆，不能管理账号。
- **私聊连发**：最后一条消息后默认安静 **3.5 秒**再处理，可改 0.3～10 秒。默认持续收集最多 15 秒；调高等待时上限至少为等待时长的两倍。生成期间有更新的输入时，旧事件在请求前、生成后及发送装饰阶段检查版本，过时回复不再发送；原始输入保留，最新一轮可从 PG 读取先前尚未回答的输入。
- **群内提及**：回应明确 @ 的提问或主动选定引用时保留 @ 目标；自然参与群聊时不强制 @。引用目标可以是本批较早一条消息。
- **附件**：只有决定接话后才解析本批文字、图片、文件和引用，避免对每条无人需要回答的图片都调用视觉模型。

“看群后私聊给主人分享”、离线历史补抓，以及 B站 / 小红书自主浏览仍未实现。本轮只处理在线新群消息与群内接话。

## PG 与隔离

各条真实用户消息分别写入 `messages`；引用和附件资料各自关联原消息。当前批次以完整、有来源 ID 的输入交给模型，历史窗口停在批次第一条之前，避免把本批内容同时当成历史和当前输入重复注入。

同一批次只生成一轮助手回复，助手记录关联最后一条真实输入。QQ 回复在实际发送钩子记录，过时且没有发送的生成结果不冒充已发生的对话。记忆确认、纠正和人设申请的来源校验可匹配本批真实原话；引用、文件、模型自己的陈述不能代替用户证据。

私聊保持 `webchat:owner` 与 Web 共用人设和记忆。扫描模式使用“平台实例 + 群号 + Bot 账号”的独立群房间，原文附真实说话人，日整理要求保留事实归属；同群多成员使用统一的原生会话锁。旧 @ 模式的按成员记录保留原样。群内不读取主人的私人历史、核心事实或私聊 L1，L0 继续共用；群消息不重置私人主动联系计时，不能提出全局人设修改。

`qq_chat_settings` 保存聊天方式，`qq_group_scans` 记录接话/安静/失败与理由，页面显示最近 20 次。API Token、缓存和费用沿用 `api_usage` 的真实返回统计。关闭扫描、设置引用为“不引用”即可停止对应行为；回退旧提交后新表保留，不删除原始数据。

## 连发缺陷证据

实际数据库中四条“然后／我／还／给你”在约 5 秒内发出，最长间隔约 3 秒，原 1 秒静默窗口分别放行；API 记录证实产生四次调用且后续轮次出现乱序。修复同时增加可调等待与输入版本检查，不只调大计时数字。

## 人设申请回执修复

发现的实际故障是模型把 `<tool_call>...</tool_call>` 作为普通文本发出，参数还使用了旧的 `change` 字段，未真正调用申请工具，因此后台没有记录。

现在明确提供原生工具参数；真实调用返回 PG 申请编号和状态。对主人本轮明确请求人设修改时产生的单个文本草稿（旧 `<tool_call>` JSON 或 DeepSeek DSML），仅兼容恢复 `companion_propose_persona`，校验字段和真实用户来源并执行一致性检查，只创建申请，不执行批准。其他工具、无明确修改语境的代码示例、无效参数均不会因此执行。

“已进入待审”必须对应真实 `pending` 记录；检查未通过、过期和缺少入库回执分别说明。相关私聊轮次等待校验后的回执再输出，避免 Web 流式输出先展示未经核实的成功声明。普通聊天继续沿用原流式策略。后台进入修改审批时主动刷新，停留时每 15 秒更新一次；编辑草稿和打开的确认对话不会被自动刷新覆盖。

历史失败申请已按真实聊天证据恢复到待审，未改动生效的 L0 / L1；具体编号与验证记录保留在本机。聊天中的“同意”仍不是批准。

## 启动凭据修复

Windows 当前用户的 `DEEPSEEK_API_KEY` 环境变量优先，其次为进程环境变量，再回退到 `local_config.json` 的凭据文件。支持 TXT 和 DOCX。读取当前用户的持久化变量可避免托盘进程继承旧环境导致必须注销或重启电脑。

原先 Key 文本文件被删除会让后台立即退出；用户提供的新 Word 已用于设置用户环境变量，启动恢复正常。源码和本地配置均不保存 Key 明文值，也不打印值；环境变量按用户要求保存在本机用户环境中，不进入 GitHub。
