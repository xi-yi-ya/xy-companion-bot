# QQ 引用、群聊 @ 与连发合并

2026-11-01，插件 v0.6.0。复用 AstrBot / OneBot 的 Reply、At、消息接收和原生模型链路，在项目插件内增加 PG 适配；未安装额外的消息防抖插件或分类模型，未修改 vendor。

## 行为

- **引用**：QQ 中引用一条消息继续提问，Bot 能读取原文、发言人及可解析的图片/文件。引用资料单独存入 PG，不当成当前用户自己的原话。Bot 的正常聊天回复会引用本轮最后一条真实输入消息。
- **群聊**：群内成员必须明确 `@Bot` 才启动一轮回答，回复同时 @ 提问者。普通发言、`@全体`、只引用 Bot、纯文本伪造的“@Bot”均不启动回答。账号完成主人绑定后才开放这一路径；私聊仍只接受绑定主号。
- **1 秒合并**：同一会话、同一发送人在最后一条消息后安静满 1 秒才处理。窗口内新消息会重置计时；群聊首条已 @Bot 时，同一人的后续补充可在该窗口内不重复 @。不同群、不同成员和私聊分别排队。
- **等待上限**：持续连发时单轮最多收集 5 秒，再开始下一轮，避免一直等不到回答。命令跳过等待。已进入模型生成的上一轮不取消，后续轮次继续走框架会话锁。
- **附件**：文字、图片、文件和引用按原输入顺序收集，各自解析后合并理解。网络读取和图片识别的耗时发生在 1 秒收集窗口之后。

本轮只加入响应式群聊，不采集未触发对话的群消息；群聊自主观察和 B站 / 小红书浏览仍是后续研究方向。

## PG 与隔离

各条真实用户消息分别写入 `messages`；引用和附件资料各自关联原消息。当前批次以完整、有来源 ID 的输入交给模型，历史窗口停在批次第一条之前，避免把本批内容同时当成历史和当前输入重复注入。

同一批次只生成一轮助手回复，助手记录关联最后一条真实输入。记忆确认、纠正和人设申请的来源校验可匹配批次中任意一条真实用户原话；引用、文件、模型自己的陈述不能代替用户证据。

私聊保持 `webchat:owner` 与 Web 共用人设和记忆。群聊使用独立的“平台实例 + 群号 + 发送人”作用域，不读取主人的私人历史、长期事实或私聊 L1；L0 固定人设继续共用。群聊消息不重置私聊主动联系的计时，群聊中不能提交全局人设修改。

## 人设申请回执修复

发现的实际故障是模型把 `<tool_call>...</tool_call>` 作为普通文本发出，参数还使用了旧的 `change` 字段，未真正调用申请工具，因此后台没有记录。

现在明确提供原生工具参数；真实调用返回 PG 申请编号和状态。对主人本轮明确请求人设修改时产生的单个文本草稿（旧 `<tool_call>` JSON 或 DeepSeek DSML），仅兼容恢复 `companion_propose_persona`，校验字段和真实用户来源并执行一致性检查，只创建申请，不执行批准。其他工具、无明确修改语境的代码示例、无效参数均不会因此执行。

“已进入待审”必须对应真实 `pending` 记录；检查未通过、过期和缺少入库回执分别说明。相关私聊轮次等待校验后的回执再输出，避免 Web 流式输出先展示未经核实的成功声明。普通聊天继续沿用原流式策略。后台进入修改审批时主动刷新，停留时每 15 秒更新一次；编辑草稿和打开的确认对话不会被自动刷新覆盖。

历史失败申请已按真实聊天证据恢复到待审，未改动生效的 L0 / L1；具体编号与验证记录保留在本机。聊天中的“同意”仍不是批准。

## 启动凭据修复

Windows 当前用户的 `DEEPSEEK_API_KEY` 环境变量优先，其次为进程环境变量，再回退到 `local_config.json` 的凭据文件。支持 TXT 和 DOCX。读取当前用户的持久化变量可避免托盘进程继承旧环境导致必须注销或重启电脑。

原先 Key 文本文件被删除会让后台立即退出；用户提供的新 Word 已用于设置用户环境变量，启动恢复正常。源码和本地配置均不保存 Key 明文值，也不打印值；环境变量按用户要求保存在本机用户环境中，不进入 GitHub。

## 验证与回退

- 隔离 PG 与异步测试覆盖引用来源、批次顺序、并发与取消、收集上限、群触发规则、私聊隔离、申请回执和凭据读取。
- 本地模拟 OneBot 连接接入真实 AstrBot 和 DeepSeek，验证三条连发只回一次、引用最后一条并 @ 提问者、读懂被引用消息、普通群消息不触发、原始消息分存。回复由测试连接接收，没有发往真实 QQ 群。
- Web 实际上传 DOCX / 图片、继续追问、读取链接及申请入库另行验收；技术会话只清理其自身记录，保持真实用户计时和人设。
- 真实手机 QQ 的显示与长期使用仍需正常聊天观察；不能将模拟连接测试描述为已向真实群发送验收消息。

回退 QQ 适配可恢复此前的私聊门禁与消息处理文件，保留本次环境变量启动修复；不需要删除 PG 原始记录、记忆或现有人设。未创建数据库备份，未清空正常聊天。
