# QQ 消息节奏与短期续聊

v0.12.0。功能只扩展本项目插件，不修改 AstrBot 源码、原有人设或记忆衰减规则。

## 架构分析与参考边界

当前输入链路是 `QQIngress → QuietWindow → PG 原始输入 → 人设/记忆/历史 → LLM`。私聊已有安静窗口，群聊已有扫描窗口，输入修订号可阻止过时生成结果。原先只在模型完成时检查一次，不能阻止等待发送期间到来的新输入。AstrBot 内置的正则分段配置在本项目中关闭，其独立发送循环也不能提供本项目需要的逐气泡修订检查。

现有 `ContactService` 每 60 秒检查一次，`ContactStore` 使用 PG advisory lock、`current_run`、租约、`awaiting_reply` 和发送审计；QQ 操作通过 `QQAgent.execute` 统一检查权限、急停、账号身份和幂等键。这些机制继续使用，不新增发送队列或后台定时器。

参考 [Starlit](https://github.com/Unclecheng-li/starlit) 的公开 README 搜索索引，适合借鉴的设计是：按最后输入计算总延迟、自然多气泡、分钟级续聊以及发送前多层抑制。不采用它的情绪/关系数值或高频主动参数，也不改变阿深的人设。2026-11-02 的 GitHub connector、网页直读和 `git ls-remote` 均返回仓库不存在；搜索索引仍能看到 README，其中声明 MIT。**未取得当前源码、提交号和 LICENSE 原文，不能声称完成源码审计或许可核验。** 本次代码独立编写，未复制 Starlit 代码或素材，NOTICE 记录设计参考。以后若取得源码并复用，须先核实对应版本许可证和版权声明。

## 拟人化消息节奏

入口：**Bot 设置 → QQ 连接 → 拟人化消息节奏**。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 开关 | 开启 | 关闭后单气泡、无模拟延迟；保留取消和防重 |
| 延迟范围 | 1.5～5 秒 | 可设 0～10 秒；首条计算总延迟，扣除合并/生成耗时 |
| 分段 | 自然段与语义停顿 | 可选仅自然段、单气泡；原设置值兼容 |
| 每轮气泡数 | 随内容决定 | 无固定三条上限；短回复仍可单条 |
| 后续气泡间隔 | 单次最多 1.2 秒 | 长度与随机抖动决定；整轮后续模拟等待合计不超过 4 秒及设置的最大延迟 |

阅读负担、回复长度影响首条等待，仍扣除合并/生成耗时。分段只在原文上切片，以换行、句末标点、长句逗号和转折/承接词作为轻量语义线索，比较段内候选切点，优先完整句并避免留下孤立短尾句，不再限制三个气泡或仅处理 450 字以内文本。短句可合在一起，长句可在自然停顿处断开；长度只用于选择边界，没有固定每条字数，也不在没有安全边界时硬切。

代码围栏（含未闭合围栏）、常见列表/嵌套缩进、引用块和管道表格作为完整单元；内联代码、链接、引号内容与数字局部保护，不会让整条回复都失去分段能力。内部切片保留原始顺序、标点、空格和 CRLF/空行，直接拼接原始切片与输入逐字一致。发送前单独移除每个气泡首尾的空行：原段落间隔由气泡边界承接，不能以 `\n\n` 继续撑高气泡。代码缩进、引用/列表内部空行保留；发送回执和已发记录采用同一份显示文本。不添加语气词、省略号，不调用额外模型，不修改生成内容或人设/系统提示词。超长代码块、列表或无安全边界文本仍可能单条发送，受 QQ 原生长度限制。

每个会话共享一把发送锁，群内不同发言者共享群锁；短期和长期主动消息也进入主号同一把锁。沿用当前响应任务执行，不后台脱离事件另发。每 0.1 秒检查输入修订和急停，每次真正发出前再次走 QQAgent 权限检查。新输入、设置变化、离线或发送结果不确定时，停止剩余部分。QQ 空状态通知不算新输入；接管发送或丢弃过时回复时清除 AstrBot 待发结果，避免框架重复发送原文。已经进入网络的消息无法保证撤回。

引用和定向 @ 只放在第一个气泡；输入合并窗口保持原设置。已确认发送的气泡逐条落入 PG，未发送尾段不写为“已经说过”。`qq_reply_runs` 记录来源领取、发送数量和终止原因，`qq_operations` 保存每个气泡真实回执。进程崩溃/热重载后不重放旧任务；发送结果不确定不重试。图片、文件、工具主动发消息沿用现有适配链，不拆成文本气泡，也不声称已经统一控制所有工具的输出节奏。

## 主动续聊

入口：**Bot 设置 → 主动联系 → 短期主动续聊**。

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| 独立开关 | 开启 | 不改变长期主动联系开关或用户已有间隔 |
| 时间窗口 | 8～20 分钟 | 可设 2～120 分钟；从主号 QQ 对话完整回复后随机计时 |
| 发送上限 | 2 次 / 滚动 24 小时 | 可设 1～6 次；并非到点必发 |
| 判断上限 | 发送上限的 2 倍 | 默认最多 4 次候选检查/日，跳过也占候选检查额度 |
| 随机门控 | 50% | 到期后可以直接放弃，不调用模型 |
| 免打扰 | 复用长期联系设置 | 北京时间；短期候选直接放弃，不堆到早晨补发 |

只为**绑定主号的真实 QQ 私聊完成回复**安排候选；不向群、其他好友或 Web 推送短期续聊。任何主号 QQ/Web 新输入都会取消旧候选，新的 QQ 对话完成后重新评估。明显道别、睡觉、去忙、等待用户回答或内容过短的对话，在本地直接排除；模型到期再判断是否还有具体且有价值的补充。自然收尾不强行重开，不把“很久没说话”本身当作值得续聊的理由。

候选保存于 `proactive_state.followup_*`，领取、生成、取消、发送复用 `proactive_deliveries`，用 `kind=followup` 区分。与长期联系及空间分享共用 `awaiting_reply` 和已有唯一索引：任何一种主动消息送出/结果不确定，都等待你再次发言，不继续追发。短期续聊跳过/生成失败不会改动长期排期，也不自动重试同一候选。

重启保留尚在有效窗口内的候选；过了最长窗口加两分钟调度宽限就放弃。中断生成的候选不重试；中断发送记为未知并等待回复。离线期间不调用模型，恢复后只处理仍有效的候选。发送前再核对最新用户消息、人设版本、开关、免打扰和目标账号，权限/急停仍由 QQAgent 最终检查。

## 人设、记忆、成本和可观测性

沿用 `companion_context` 构建 L0 > 已批准 L1 > L2、近期完整历史与摘要；随机归档仍是每轮一条，读取不强化。续聊不是用户输入，没有工具权限，不批准人格或改写核心事实。每日整理、初始 10 级、每 48 小时降低一级、低于 7 归档均保持不变。

节奏与分段不调用模型。正常回复不附加额外的“续聊分析”调用；到期通过本地筛选的候选，用**一次现有 DeepSeek Flash 调用合并判断和写作**，可返回不发送。输出预留 700 Token，正文最多 250 Token；输入沿用动态上下文预算，不另建记忆。实际成本取决于历史长度和缓存命中，默认最多四次后台判断/日；手动预览额外计费，不算后台候选。API 实际输入、输出、缓存、费用分别记录到 `followup` / `followup_preview` 分类，可在用量页面查看，不能把“最多发两条”误当成只花两条短输出的钱。

页面显示当前候选时间、取消原因和最近一次续聊结果；完整最近记录区分长期/短期类型。常见原因：`user_returned` 新输入、`conversation_closed` 已收尾、`waiting_for_answer` 等回复、`quiet_hours` 免打扰、`random_skip` 随机放弃、`frequency_limit` 限频、`window_expired` 已过窗口、`settings_changed` 配置变化、`interrupted_no_retry` 重启取消。模型判断的原因也会保存。
