# 后续研究方向

记录日期：2026-11-01（北京时间）。

本文是项目方向与待研究问题，不代表功能已经实现。群聊观察分享、自主浏览 B站和小红书目前仅记录，暂不开发、安装插件或开启自动任务；现有聊天、记忆、人设及主动联系配置保持原状。

## 近期需求：已实现，验收说明见 QQ 聊天文档

- QQ 引用：理解被引用的原消息，以及回复时引用对应消息。优先复用 AstrBot / OneBot 原生能力。
- 群聊回答：只有明确 `@Bot` 才触发公开回复；普通发言、`@全体`、单纯引用不触发。
- 连发合并：最后一条消息后安静满 1 秒再处理，期间有新消息则重新计时；按会话和发送人隔离，保留文字、引用、图片和文件的顺序。原始消息分别保存在 PG，合并后生成一轮回复。

调研过 [continuous_message](https://github.com/aliveriver/astrbot_plugin_continuous_message)、[TurnFlow](https://github.com/Yuimi-chaya/astrbot_plugin_turnflow) 和 [debounce](https://github.com/advent259141/astrbot_plugin_debounce)。最终在现有插件内实现轻量的 QQ 适配，以保留 PG 原始记录、附件解析和来源校验；没有安装这些第三方插件。实现及验证边界见 [QQ 聊天能力](QQ_CHAT.md)。

## 方向一：自主观察群聊，发现值得分享的内容

目标：Bot 可以了解指定群正在聊什么，发现自己感兴趣、与你有关或想与你讨论的内容，通过 QQ 私聊分享给你。

“观察群聊”和“在群里回答”分别控制。未来允许在指定群静默观察时，群内公开回答仍遵守明确 `@Bot` 才触发的规则。

待研究流程：

1. 从选定群接收在线期间的新消息，保留群号、消息 ID、时间和发言人等来源。
2. 将连续发言整理为话题片段，识别引用、群内梗、链接和必要附件。
3. 结合 L0、已批准 L1、用户明确兴趣及近期话题，判断哪些片段值得进一步阅读。
4. 形成少量分享候选，保存来源、简要内容和“为什么想分享”，允许选择保持安静。
5. 经统一的主动消息调度器，在合适的时机私聊分享；后续能找回对应群聊来源。

需核对的重点：群与成员之间的上下文隔离、是否需要补读离线历史、可获取历史的范围、引用和附件的完整性、同一话题去重、群消息撤回后的处理，以及多群繁忙时的模型调用量。

参考线索：[private_companion 的群观察设计说明](https://github.com/menglimi/astrbot_plugin_private_companion/blob/main/docs/WORKING_PRINCIPLES.md)、[context_aware](https://github.com/muyouzhi6/astrbot_plugin_context_aware)。仅作为后续源码调研入口，不表示已验证与本项目兼容。

## 方向二：自主浏览 B站和小红书

目标：Bot 能根据自己的角色兴趣和长期相处形成的交流话题，自主选择浏览方向，发现值得与你分享的视频或笔记，也保留少量自由探索。

| 来源 | 拟研究的浏览方式 | 理解内容的重点 |
| --- | --- | --- |
| B站 | 推荐流、关注更新、关键词搜索、指定 UP 或视频池 | 标题与简介、字幕、必要的画面和评论；准确区分实际读取的范围 |
| 小红书 | 推荐流、关键词搜索、指定账号和笔记 | 图文正文、图片中的文字与视觉信息、视频可用内容及必要评论 |

候选方案：

- [astrbot_plugin_bilibili_ai_bot](https://github.com/chenluQwQ/astrbot_plugin_bilibili_ai_bot)：已有主动选片、内容理解与给主人分享的设计，可研究其浏览流程。插件还包含独立记忆、兴趣及主动行为模块，需评估如何复用读取能力并衔接本项目 PG 与人设规则。
- [polylens-bilibili-mcp](https://github.com/liu-xindi/polylens-bilibili-mcp)：作为 B站推荐、搜索和内容读取的工具层候选。
- [xiaohongshu-mcp](https://github.com/lightaddark/xiaohongshu-mcp)：作为小红书搜索、推荐和笔记详情的工具层候选；需进一步核对账号登录、返回内容、Windows 本地运行及维护状态。
- [astrbot_plugin_multi_parser](https://github.com/Qfxaile/astrbot_plugin_multi_parser)：可研究用户发来的 B站 / 小红书链接解析，与自主发现内容配合。

以上只完成候选发现，没有部署或真实账号浏览验收。实施前需按当时版本核对源码、协议、依赖和能力；登录方式与会话保存也留到实施阶段处理。

内容理解必须保留证据层级：只看标题时说明只看到标题；读过字幕、正文或关键画面时记录实际范围。无法读取的视频或笔记保留失败原因，不生成“看完了”的记录。

## 与现有系统的衔接原则

- **人设**：浏览方向参考 L0 和已批准 L1；看到的内容不能自行改写核心人设或长期习惯，修改仍走现有人工审批。
- **记忆**：群聊与自媒体材料单独保存为外部来源。Bot 浏览过的内容、群友的经历和用户本人的事实分别标记；共同讨论后，按既有规则整理真正形成的共同经历。
- **衰减**：保留每日整理、初始 10 级、每两天降一级、低于 7 归档、用户提及或确认才恢复、每轮随机读取一条归档等现有规则。后台阅读不自动强化用户记忆。
- **分享**：群聊、B站和小红书共用发送去重、免打扰和等待回复状态。初步考虑将有趣内容作为下一次主动联系的话题；“发现后立即推送还是等到 10～14 小时联系窗口”是后续待定项，当前规则不变。
- **本地运行**：沿用本机服务与 PG，支持暂停浏览、关闭某个来源、重启后恢复检查点；离线期间不假装正在浏览。
- **可观测性**：记录浏览来源、成功读取范围、分享理由、重复过滤、真实 Token、缓存、耗时和费用；候选生成与实际送达分别记录。

## 后续验证顺序与停止条件

1. 基础引用、群聊 `@` 和 1 秒合并已经实现；先在日常聊天中观察其稳定性。
2. 选一个群验证只读观察，在 Web 展示候选与依据，检查普通群消息不会触发公开回复。
3. 先接通一个自媒体来源，验证搜索 / 推荐、读取与来源回看；B站和小红书分别验收。
4. 验证 PG 来源隔离、兴趣选择与人设稳定，再研究跨来源的统一分享。
5. 最后接入实际私聊分享，验证免打扰、未回复暂停、重复内容过滤与发送结果不确定时不重发。

验收以真实来源可回看、内容理解有依据、跨来源不串记忆、分享频率可控为准。账号不可用、接口连续失败或费用超过实施时确定的上限时，暂停对应来源并保留错误记录；关闭观察 / 浏览开关即可回退到现有聊天模式。

群聊观察及自媒体方向仍仅记录研究方案，不创建其数据表、账号会话或调度任务，也不执行群消息采集、自媒体浏览及对应主动分享。
