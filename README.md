# 本地陪伴 Bot

AstrBot v4.29.4（`61335414433db721b3f7ecc93f90deafe0a59d78`）+ 自研插件 + 本机 PostgreSQL。

[QQ 聊天能力](docs/QQ_CHAT.md)：按需引用、默认每 10 秒查看群聊新消息并自主接话、可调的私聊消息合并窗口（默认 3.5 秒）、生成中过时回复拦截，人设申请返回真实入库回执。配置入口为 **Bot 设置 → QQ 连接 → 聊天方式**。

[QQ 自主管理方案](docs/QQ_AUTONOMY.md)：头像、签名、状态和表情包的接口与现成插件核查；尚未开放这些账号操作权限。

[QQ 空间](docs/QZONE.md)：默认随机 15～30 分钟读取好友动态，按现有人设与记忆生成阅读笔记和私聊分享候选；可在 **Bot 设置 → QQ 空间** 调整浏览/分享开关与间隔。分享沿用既有主动联系限制，点赞、评论和发布未开放。空列表不会编造内容。

[PoolClosed 修复](docs/RELOAD_LIFECYCLE.md)：修复插件重载后 SDK 计量钩子引用旧连接池的问题，真实聊天连续两次重载验证通过。

[后续研究方向](docs/RESEARCH_ROADMAP.md)：群聊观察与私聊分享、自主浏览 B站 / 小红书。当前仅记录方向，暂不实施。

## 启动与使用

1. 双击桌面“陪伴Bot”快捷方式或本机 `runtime/desktop/CompanionBot/CompanionBot.exe`。也可用 `Start-Bot.vbs`、`Start-Bot.cmd` 或 `启动陪伴Bot.ps1` 打开托盘 GUI。服务已运行时会连接现有实例，重复打开只显示已有窗口。
2. 打开 `http://127.0.0.1:6185/#/chatbox`，本机免账号登录。
3. 在 AstrBot 的 Chat 中创建会话并聊天。
4. 点击聊天页右上角 **Bot 设置**，可以编辑 L0 固定人设、查看 L1 长期习惯、审批 Bot 修改申请、查看 L2 记忆及规则、管理自主上网，或查看“用量与连续性”。保存或批准后从下一条消息生效，设置保存在 PostgreSQL。也可直接打开 `http://127.0.0.1:6185/#/plugin-view/astrbot_plugin_companion_memory/memories`。
5. 可手动整理今天；自动任务在北京时间 03:00 之后整理未完成日期。关闭电脑时不运行，下次在线补做。

## 托盘与桌面 GUI

**QQ 主动联系**：在 **Bot 设置 → 主动联系** 管理。默认开启，用户最后发言后随机等待 10～14 小时，免打扰为北京时间 00:00～08:00。发出一条后等用户回复，QQ/Web 的新消息都会重新计时；共用现有 PG 人设和记忆。可生成不发送的预览，查看排期及记录。电脑与 Bot 需要保持在线，详见 [主动联系说明](docs/PROACTIVE_CONTACT.md)。

托盘主要显示 **正在运行 · 空闲** 和 **正在运行 · 忙碌**。回复、搜索/读网页、每日记忆整理和设定检查期间，状态跟随真实任务变化；结束、异常或取消都会清除忙碌。图标空闲为绿色，忙碌为暖黄色。启动、停止或故障时显示对应的必要状态。

右键托盘可打开聊天、Bot 设置和小控制窗口，或停止/启动、退出。关闭控制窗口会收进托盘，Bot 继续在线；“退出（停止 Bot）”先调用 AstrBot 原生关闭流程，清理插件与连接，再退出托盘。PostgreSQL 服务保持运行。后端未及时响应时，控制器只会结束此项目确切路径对应的 Python 进程，不处理其他项目或数据库进程。

GUI 与后端分别限制单实例。后台进程存在且 Web、插件、数据库都就绪才显示运行中。打包程序只包含托盘与控制窗口，后端继续使用项目 `.venv`，模型、记忆和凭据仍留在原位置；因此它是当前本机安装的 EXE 启动器，**不能只复制 EXE 到另一台电脑使用**。请保留整个 `CompanionBot` 输出目录及现有项目环境。

从源码重新打包：

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-gui.txt
.venv\Scripts\python.exe build_gui.py
```

输出为 `runtime/desktop/CompanionBot/CompanionBot.exe`。构建使用临时的干净 PATH，防止 PostgreSQL 的同名 ICU DLL 被误打包；不会修改系统 PATH 或 PostgreSQL 安装。命令行回退入口仍可用 `.venv\Scripts\python.exe start.py`，管理入口为 `.venv\Scripts\python.exe manage_bot.py status|start|stop`。

`local_config.json` 保存模型和备用凭据文件路径。启动优先读取 Windows 当前用户环境变量 `DEEPSEEK_API_KEY`，其次进程环境，再回退到配置的 TXT / DOCX 文件；设置好用户环境变量后，不再依赖原临时文本文件。AstrBot 配置只保存环境变量引用 `$DEEPSEEK_API_KEY`。

PostgreSQL 连接凭据在 `%USERPROFILE%\.codex\credentials\postgresql-local.json`，由 Windows 当前用户 DPAPI 加密；`local_secrets.py` 负责读取。本项目只使用 `companion_bot` 数据库。此凭据不能直接复制到其他 Windows 账号或另一台电脑使用。

免登录模式通过本地适配层保留原来的内部用户身份，因此已有聊天和记忆不变。服务固定监听 `127.0.0.1`，并验证实际连接地址、Host、Origin；该模式用于本机浏览器，不用于公网部署。上游 AstrBot checkout 不做改动，页面入口通过本地适配层加载。

## 人设和人工授权

QQ 和 Web 均可读取 DOCX、PDF 文字层、TXT / MD / CSV / JSON、XLSX、PPTX 及常见图片；公开链接与 QQ 链接卡片沿用联网开关自动读取。解析材料保存到 PG，后续可继续讨论，不把文件内容直接当成用户事实。旧版 DOC / XLS / PPT 请另存现代格式，扫描 PDF 可发页面图片。详见 [附件解析与限制](docs/ATTACHMENTS.md)。

| 层级 | 内容 | 生效与生命周期 |
| --- | --- | --- |
| L0 固定人设 | 名字、性格、说话方式、行为边界、世界观 | 每轮注入，最高人设优先级，不衰减 |
| L1 长期习惯 | 称呼、表达习惯、共同梗、互动风格 | 只注入已批准且未暂停的习惯，不参与普通记忆衰减 |
| L2 记忆 | 用户事实、共同经历、日常事件 | 按预算注入，普通记忆每两天降一级；用户核心事实不衰减 |

L0 / L1 与 L2 使用不同的表、写入路径和更新任务。L0 完整注入，上限 6000 本地规划 Token；L1 合计 6000，不再限制十条习惯。超限明确拒绝写入，不悄悄删掉旧设定。界面显示已保存人设的分词长度。

Bot 可以调用 `companion_propose_persona` 提交具体的 L0 / L1 修改申请，**工具没有执行或批准权限**。申请记录旧值、新值、理由、真实用户消息来源及人设版本，经模型一致性检查后进入待审。你需要在“修改审批”中逐条点击批准并确认，程序才写入生效设定；聊天中的“同意”不算授权。检查失败、被拒绝或已过期的申请不能批准。

L1 每日候选从近 30 天按天分层抽样，每天最多 12 条、最多 360 条用户消息，输入另受 48000 Token 预算限制；至少有 6 条消息、跨 3 天才调用模型。每条自动候选需至少 3 条消息、跨 2 天的证据，每天最多 3 条。每天只生成候选，不自动应用。手动检查与定时任务共享日期任务，不在每轮聊天额外生成习惯摘要。

修改 L0 会让旧申请过期，并暂停已有 L1。暂停习惯可点击“重新申请检查”，检查后仍需再次批准，或直接撤回。批准或撤回 L1 后，基于旧习惯的一批待审申请也会过期，避免互相冲突的旧申请覆盖新状态。审批和人设修改保留审计记录；一致性判断仍依赖模型，最终由你决定。

## 记忆规则

- 普通记忆等级为 `max(0, 10 - floor(距离用户上次提及的秒数 / 172800))`，连续 8 天未提及归档；核心记忆不参与衰减。
- 每天一个整理任务；只处理新增消息，有日期检查点。每批总输入规划 72000 Token，长日不限八批，超长单条分片；按连续来源前缀提交检查点，失败从已提交位置继续，每个失败位置最多自动尝试 3 次。
- 新记忆和变化必须引用原始用户消息。整理使用用户消息时间，不用任务运行时间恢复等级。
- 每轮随机读取一条有效归档记忆。检索、随机抽取、查看页面和 Bot 自己提起都不会恢复等级。
- 用户重新提及/确认由主聊天模型按需调用确认工具；程序验证用户身份、当前消息及逐字证据。不为每轮聊天再调用一个摘要模型。
- 用户否认时可立即失效旧记忆，更新内容由每日整理提取。旧版本与来源保留。
- 每轮记忆总上限 30000，按相关性、重要性和时间选择，不填满无关信息。核心事实 8000、活跃 12000、相关归档 8000、单条随机归档 2200 共享总上限。随机读取不刷新等级，超出手动小预算时明确标注节选。
- 通过 `mark_as_temp()` 注入单轮记忆，不把记忆块不断叠加进后续历史。
- 数据库故障时不继续无记录地调用聊天模型；界面返回明确失败，恢复后重试。

## 上下文与费用

使用官方 `deepseek-flash`，当前已核实为 DeepSeek-V4.1-Flash；模型上下文 1048576、物理最大输出 393216。项目禁用思考模式，日常回复上限 12000，整理输出 16000、连续性摘要输出 10000。以官方 JSON Tokenizer 在本机规划，实际费用采用 API usage，工具 schema、帧格式、图片开销另有预留。[完整审查、预算依据、费用情景与验证结果](docs/CONTEXT_DESIGN.md)。

近期原文随交流自然增长，观察档位为 24000 → 90000 → 240000；并不预先填满。达到 216000 后后台压缩较早历史，保留约 168000 的近期完整轮次，摘要最多 12000。连续短回复不会缩小深入交流的上下文；相隔八小时重新开始时，可在后台将旧话题整理为摘要，保留最近约 16800 原文。原始记录一直保留，模型有独立的原始历史检索工具。框架原来的二十轮裁剪被本地适配层按本插件标记绕过，上游源码未修改。

摘要保留关系、事实变化、情绪缘由、未完成事项、共同经历和关键原话，附消息来源；关键原话逐字校验。失败不推进覆盖检查点，也不丢掉未摘要原文；任务退避重试并显示错误状态。常规应急历史与摘要按 480000 工作窗口规划，工具与安全余量各 32000，SDK 层对最终完整输入作模型物理窗口检查；供应商拒绝上下文时也不允许框架弹出旧记录重试。

“用量与连续性”显示真实输入/输出、缓存命中、分类日/月费用估算、首 Token/总延迟、输出达到长度限制的次数、缺失 usage、最近的原文与摘要覆盖、召回选择。峰谷费率与中国节假日可能影响账单，界面给出估算范围。还提供每天 100/300/1000 次回复、不同缓存率及轻聊/持续长聊的费用情景；不会把 95% 缓存当作保证。检索相似度不是准确率，准确性需带答案回放及真实使用持续评估。

## 自主上网

聊天模型可按需调用 `companion_web_search` 搜索公开资料，调用 `companion_read_web` 读取网页 Markdown，回答时附来源链接。需要最新信息、核实不确定事实或用户要求查询时使用，普通闲聊不强制联网。当前接入 [DeepSeek 官方 Search / Fetch](https://api-docs.deepseek.com/guides/search/)，复用现有 DeepSeek Key，不增加搜索供应商凭据。

“自主上网”页提供开关、每轮最多调用次数、网页内容预算和最近 20 次记录。默认启用，每轮最多 3 次（可设 1～5）、内容预算 12000（可设 2000～24000 本地规划 Token）。并发工具共享同一轮预算；网络错误不自动重试。Key 只发往固定的 DeepSeek API 域名；用户 URL 作为 Fetch 数据传递，不开放本机文件、浏览器账号或本地服务。

搜索和网页读取按服务商成功请求数计费，费用以官方说明为准。只发送必要查询词或页面 URL，网页结果属于外部参考，不授予修改人设的权限，也不自动写入用户记忆。Bot 在当前聊天中决定何时上网，后台没有持续爬取任务。
